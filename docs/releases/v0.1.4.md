# DevType v0.1.4

DevType v0.1.4 makes the menu bar useful during password entry: when macOS
Secure Input is active, it shows a key icon and **Copy Secret**. Open the menu,
choose a saved secret, authenticate if required, then paste with **⌘V**.

## Password-field experience

- Promotes the existing **Copy Secret** submenu to the first action position
  while Secure Input is active, including when expansion is manually paused
  or engine permissions need attention.
- Keeps the selected workflow stable while the menu is open. Focus changes,
  snippet updates, and preference changes cannot rearrange secret rows under
  the pointer; closing the menu restores the current status.
- Adds localized guidance in English, Korean, and Japanese, including
  VoiceOver help. The key icon follows light, dark, and highlighted menu
  appearances, and the action always has a visible text label.
- Corrects the secure-input tooltip to describe mouse selection and manual
  **⌘V**, rather than recommending a shortcut that Secure Input can suppress.
- Keeps empty-library guidance and secret search available through the existing
  submenu. Permission recovery and engine diagnostics remain in the menu.

## Reliability and security

- Menu-bar refreshes read Secure Input live instead of replaying a delayed
  monitor snapshot.
- Monitor generations reject notifications queued before stop or restart.
  Timer ownership and transition tracking share one lock, deinitialization
  cancels monitoring, and invalid polling intervals are bounded.
- Typed expansion remains blocked during Secure Input. The change reuses the
  existing secret resolver, authentication policy, concealed clipboard, and
  clipboard expiry; displaying the action does not read or copy a secret.
- Updated the user, support, architecture, development, and security docs to
  explain the new interaction and distinguish signing from notarization.

## Local build and distribution status

The local v0.1.4 build uses the existing **Apple Development** signing identity
and is **unnotarized**. Signature verification does not establish Gatekeeper
approval or notarized distribution. The application version is stamped from
the exact `v0.1.4` Git tag; the build number is the commit count.

The local installation target is `/Applications/DevType.app`. Creating a local
commit, tag, and installed app does not publish a GitHub release. Public
publication and notarization are separate release operations.
