# DevType v0.1.4 follow-up: reliable secret selection

A single click in Search Secrets previously only highlighted a result. It did
not reach the copy callback, so it neither requested Touch ID nor copied the
password. Copy-mode palettes now commit the clicked result with one click.

- Copy Snippet and Search Secrets share the corrected mouse path. The normal
  command palette retains single-click selection and double-click execution.
- Arrow navigation and filtering remain noncommitting. Return and numbered
  shortcuts explicitly commit the selected result.
- Mouse actions resolve the clicked row; headers and blank results cannot
  accidentally commit a previous selection.
- All commit paths share a single completion guard, preventing a duplicate
  event from requesting authentication or copying twice.
- Copy-mode footers now say **Copy**, localized in English, Korean, and Japanese.

## Security impact

The existing authentication policy is unchanged. Selection reaches
`SecretMenuFlow.resolve`; authorization still precedes reading the value.
Cancellation or authentication failure leaves the clipboard unchanged.
Concealed clipboard markers and expiration remain enabled. Tests use synthetic
secrets in memory and a private pasteboard, without accessing user passwords.

## Verification

A native mouse-event regression reproduced the defect: the intended row was
selected, authentication was requested zero times, and the clipboard was unchanged.
The previous window test invoked the double-click action directly and missed
that single-click behavior; it now delivers real mouse events.

- **79 focused tests passed**, including six native window tests and the
  authentication, localization, and source-contract suites.
- Native checks cover the chosen result, delayed authorization, cancellation,
  authentication failure, concealed clipboard writes, duplicate action delivery,
  headers, empty results, filtering, Return, and numbered shortcuts.
- **Local CI passed**: 1,936 tests, 14 opt-in skips (seven live-AI and seven native
  window tests), no failures; debug and release builds, packaging, and bundle
  identity/signature checks passed. The six native copy-window checks above ran
  separately with their opt-in enabled.

The existing native status-button check failed at its WindowServer setup:
`XCTAssertGreaterThan failed: ("0.0") is not greater than ("0.0")` for the temporary
menu-item window height. Its assertions are retained; this check remains
unverified in this session. Physical Touch ID and third-party password-field
interaction also require manual verification.

a commit suffix and incremented build number. Apple Development signing remains
unnotarized and does not establish Gatekeeper approval.
